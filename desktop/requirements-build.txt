# desktop/requirements-build.txt - the environment that FREEZES Attune into an exe.
#
# This is NOT the app's runtime dependency list (that is pyproject.toml) and NOT the
# analysis stack for working from source (that is requirements.txt). It is a pinned
# record of the one Python environment on the maintainer's machine that has ever
# produced a working frozen build, so that machine can be reproduced.
#
# Python 3.12.10, 64-bit, Windows.
# Recorded with `python -m pip freeze` against mixer-ng\.venv-standalone on 2026-09-20.
#
# To rebuild that environment from scratch:
#   py -3.12 -m venv .venv-standalone
#   .venv-standalone\Scripts\python -m pip install -r desktop\requirements-build.txt
#   .venv-standalone\Scripts\python desktop\build.py
#
# Notes on what is here and why:
#   pyinstaller + pyinstaller-hooks-contrib + altgraph + pefile + pywin32-ctypes
#       the freezer itself and its Windows helpers.
#   pywebview + pythonnet + clr_loader + proxy_tools + bottle
#       the desktop window. pywebview pulls pythonnet for the WebView2 backend.
#   librosa + numba + llvmlite + soxr + audioread + soundfile + scikit-learn + scipy
#       the analyzer half, frozen as the separate analyzer\AttuneAnalyzer.exe.
#   onnxruntime + protobuf + flatbuffers
#       CLAP embedding and the optional learned metric head, without torch.
#   There is deliberately NO torch here: the shipped app never imports it.
#   There is deliberately NO pytest here: this environment builds, it does not test.
